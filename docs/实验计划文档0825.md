# 足球关键事件实验计划（0825）

更新时间：2026-08-25

## 1. 当前结论与目标

当前主目标不是提高 sampled clip-val F1，而是在完整长视频 dense 扫描中：

- 保持候选召回，重点报告 `Precision @ Recall >= 85%` 与 `Precision @ Recall >= 90%`；
- 降低 `FP / 90min`；
- 降低按时间并集去重后的人工参与时长；
- 改善跨视频泛化，尤其是 save、set_piece 以及 worst-20% 视频；
- DINOv3 仍作为足球事件理解主模型，verifier 只处理剩余 hard case。

当前最强证据表明，瓶颈至少包含两部分：

1. **Train-online mismatch**：训练主要看到独立采样的 10s clip，线上是 10s/stride5s 的连续重叠窗口，且真实负样本密度远高于 sampled validation。
2. **足球局部证据表达不足或迁移不稳定**：shot 主排序较好；save 与 shot 高度共现且正样本内部异质；set_piece 存在长上下文和子类差异。当前 class evidence routing 已能学习局部注意，但缺少 ball/goal/player 的显式空间监督。

这两条路线都比继续无诊断地扩大时序头、提高 LoRA rank 或增加普通随机负样本更有针对性，但必须做单变量验证。

## 3. 路线A：Online-simulation training

### 3.1 核心训练单元

将训练单元从独立 clip 改为连续 chunk：

```text
40s chunk
  -> 统一绝对时间网格（2.4 fps，共96帧）
  -> 10s window / stride 5s
  -> 7个重叠窗口，每窗24帧
  -> 共享解码、共享增强、共享DINO逐帧特征
  -> 每窗独立 clip/dense 监督
```

首版使用 40s，不直接使用 60s：40s 产生7窗，能覆盖真实上下文，同时控制显存、相关性和调试成本。

实现约束：

- 同一 chunk 内所有窗口必须使用一致的 photometric/geometric augmentation；
- 从绝对时间网格切片，不能由每个 window 各自随机采样时间点；
- 每个 GPU 一个或两个 chunk；一个 optimizer step 应覆盖至少6至12个不同视频，不能被同一视频的相邻窗口占满；
- 重叠帧只编码一次。若7个窗口分别跑DINO，计算会从96帧膨胀到168帧，失去方案价值；
- 每个窗口基于绝对事件时间重新生成 multi-label、frame curve、label mask 和 raw context span。

### 3.2 Chunk-aware sampler

推荐层级：

```text
选择采样模式
  -> 选择目标类别 / subtype / save cohort
  -> 从满足条件的视频中均匀选视频
  -> 选择事件或上下文 anchor
  -> 生成40s chunk
  -> 生成内部全部dense windows和标签
```

首轮建议配比：

- 40% event-containing chunk；
- 30% near-event context chunk；
- 30% random background chunk。

事件在40s chunk中的位置随机放在约10至30秒，不固定居中，避免位置捷径。event-containing chunk 必须保留完整几十秒背景，不能只保留事件附近的正窗。

### 3.3 Near-event negative 的安全定义

不能使用“窗口中心距离GT为5/8秒”直接判负；10s窗口可能仍包含GT边界。必须基于完整窗口区间与事件支持区间判定：

- `random_negative`：距离所有可信事件较远；
- `pre_context_negative`：窗口结束早于该事件证据开始；
- `post_context_negative`：窗口开始晚于该事件/context span结束；
- `cross_class_negative`：对目标类别可信为负、但可对其他类别为正；
- `confirmed_hard_negative`：仅限人工确认或可信 other-action 标注。

必须使用 per-class label mask：

- shot-only 可以是 save 的条件负样本，但仍是 shot 正样本；
- save 允许并应保留先前 shot 上下文；
- set_piece 使用 raw valid context span 设置保护区，鸣哨、犯规、站位聚集不得粗暴当负样本；
- 未审核、标签不完整或 detector 漏检的类别使用 unknown/ignore，不产生负梯度；
- 未人工确认的 dense 高分FP暂不作为 hard negative。

### 3.4 Cross-window consistency

该项不是首轮必选，建议在 Online-simulation 基线稳定后加入。

正确约束：

1. 只有两个窗口都包含同一 accepted event 时，才约束对应类别的 clip logits 接近；不能约束 event-window 与只含前奏的 background-window 相同。
2. dense response 在**绝对时间轴**上对齐：对重叠区域插值后约束 `z_i(t_abs)` 与 `z_j(t_abs)`。
3. 同一事件的 soft peak 应满足：`window_start_i + peak_i` 与 `window_start_j + peak_j` 接近。
4. 使用 soft-argmax/期望时间，不能使用不可导 hard argmax。
5. 使用可信标签/伪标签 mask、置信度权重，并对一侧 stop-gradient；否则存在全零或常数曲线的平凡解。

建议 loss 权重从 `0.02-0.05` 开始，在 supervised response 稳定后 warm-in。它主要用于改善边界稳定性和重叠窗口分数一致性，不代替事件判别监督，也不代替 PointNMS。

## 4. 路线B：Football-evidence-aware representation

### 4.1 方案判断

该方向可行，而且与旧 detector-crop / RGB marker 实验有本质区别：

- 旧方案主要改变输入像素或从 detector box 裁图；
- 新方案用 detector 伪标签直接监督 DINO patch representation，并把受监督的 ball/goal/player evidence token 送入事件时序编码器。

目标不是让事件模型替代通用检测器，而是让 DINO 表示保留足球事件需要的实体证据：球、球门、球员密度/交互，以及这些证据随时间的变化。

推荐结构：

```text
Frame -> DINOv3 patch tokens + CLS
                   |
          football evidence queries
          /          |           \
    ball token    goal token    player/context token
          \          |           /
        class-conditioned spatial evidence fusion
                         |
             per-frame event state tokens
                         |
             Temporal Stem/Encoder
                    /          \
             Dense curve      Clip head
```

每个事件类别使用不同证据组合，而不是一个共享 football token：

- shot：ball movement + goal relation + player action/context；
- save：shot response/history + goal/keeper-region evidence + ball evidence；
- set_piece：goal/corner/field geometry + player layout/static context，ball可选而非强制。

### 4.2 为什么不能直接做普通检测 head

当前输入512x896、patch size16，空间网格约32x56。很多足球目标小于一个patch：

- patch feature 无法恢复亚patch级精确框；
- detector 漏球严重，`没有球框`不能被解释成`没有球`；
- 用 box regression 或密集背景负样本会让模型主要学会输出无球；
- player detection 容易、样本多，若权重不平衡会淹没真正稀缺的 ball signal。

因此首版不是训练完整检测器，而是训练低分辨率、置信度感知的 evidence heatmap/query routing：

- 将 detector box 中心映射到 patch grid；
- 球使用最小1至2个patch半径的 Gaussian soft target，不要求精确边框；
- 球门使用区域/soft mask；
- 球员使用低权重的人群密度或区域占用，不逐框做主任务；
- 高置信正检测产生正监督；无检测为 unknown；仅在人审/跟踪确认的空帧上产生负监督；
- teacher detection confidence、tracking continuity、二次检测来源进入 supervision weight；
- 多个候选球可使用 top-k soft target，不能强迫模型把唯一detector候选当绝对真值。

### 4.3 Feature routing，而不仅是 auxiliary loss

单纯增加 detection loss 不足以证明事件模型利用了实体证据。必须同时满足：

1. heatmap/evidence query 从事件模型实际使用的 DINO patch tokens 读取；
2. ball/goal/player token 进入每帧 class-conditioned state token；
3. state token 进入主 Temporal Encoder；
4. 事件 loss 可以反向更新 evidence routing 与启用的 LoRA blocks；
5. detector 缺失时有 learned unknown/no-observation token，而不是把全零heatmap当真实负证据；
6. 训练时做 detector dropout、box jitter、confidence noise，防止推理依赖完美检测。

推荐融合不采用接近 identity 的小残差。第一版可使用 gated concat：

```text
state_t^c = MLP_c([global_t, patch_evidence_t^c,
                   ball_token_t, goal_token_t, player_token_t,
                   detection_validity_t])
```

但必须保留 global feature，检测失败不能导致事件召回直接坍塌。

### 4.4 监督和验收

辅助监督建议：

- `L_ball_heatmap`：置信度/跟踪连续性加权 focal或soft BCE，只监督可信位置；
- `L_goal_heatmap`：soft region BCE/Dice；
- `L_player_density`：低权重，可选；
- `L_event_clip + L_event_dense`：保持主任务；
- 初始总 detection weight 不超过主事件 loss 的10%-20%，并分别记录有效监督帧比例。

必须报告：

- ball/goal heatmap hit@patch 与有效监督覆盖率；
- event-positive 与 background 上 evidence token 的差异；
- 屏蔽 ball/goal token 后的事件 logit drop（因果利用审计）；
- detector 缺失子集与命中子集上的事件指标；
- save、shot、set_piece 在固定 recall 下的 precision；
- 完整长视频 FP/90min 与人工参与时长。

如果 heatmap 指标提高但事件指标不动，说明只学到了检测辅助任务，feature routing 无效；如果 detector-hit 子集提高但 missing 子集召回下降，说明模型过度依赖 detector；如果球监督覆盖率太低，则先改善teacher/index，不应继续加大球loss。

## 5. 实验顺序与变量隔离

### Milestone 0：固定锚点

- 完成 last8/r8 当前训练的 epoch1及后续健康检查；
- 用同一套 val15 dense cache 输出 PointNMS 1:1 tol5 指标；
- 与 last6/r8 在相同 checkpoint、阈值和长视频协议下比较；
- 确定后续固定使用 last6/r8 或 last8/r8，后续实验不再混改 LoRA depth/rank。

### E1：Online-simulation only

- 40s chunk / 10s window / stride5；
- 保持现有网络、LoRA、loss；
- 50% event-containing / 50% random background；
- 不加 cross-window consistency，不加 detection auxiliary。

目的：单独判断 train-online 对齐是否提高长视频排序和阈值迁移。

### E2：Near-event sampler

- E1基础上改为40/30/30；
- 增加 per-class near-event label mask；
- 不使用未确认 dense FP。

目的：降低等召回下的 near-event FP。

### E3：Cross-window consistency

- 只在E1/E2表明 response curve 有价值但窗口间峰值漂移明显时加入；
- 低权重、warm-in、绝对时间对齐。

### E4：Football evidence auxiliary + routing

- 固定 E1/E2 最佳训练协议；
- 增加 ball/goal 首版，player density 可延后；
- 与无 detection supervision 的 control 使用相同 init、采样、LoRA、训练预算；
- 不与 LoRA rank/depth变化捆绑。

建议先做 ball+goal，不在首轮同时加入复杂 ball trajectory、ROI crop、teacher distillation 和新时序头。

## 6. Validation 与模型选择

sampled clip-val F1保留为 diagnostic，不能再作为唯一主KPI。

主协议：

- val15 固化 per-class threshold；
- external18 untouched，只做最终报告；
- PointNMS，1:1 GT matching，tolerance=5s；
- window-overlap 仅用于UI coverage recall，不用于模型precision选择；
- 视频级 bootstrap置信区间。

每个 checkpoint 输出：

- `Precision @ Recall >= 85%`；
- `Precision @ Recall >= 90%`，若不可达则报告最大 recall ceiling；
- `FP / 90min`；
- event-level AP；
- per-video AP及worst-20% eligible-video AP；
- per-video recall P10/median；
- 零GT视频的FP/90min；
- 预测片段做跨类别、跨时间并集去重后的人工参与时长；
- full-support、capped10/15/20覆盖recall。

## 7. 预注册验收标准

相对固定control：

- 同等 recall 下 macro precision 至少提高2个百分点；
- candidate recall ceiling下降不超过1个百分点；
- FP/90min或去重人工参与时长下降至少10%；
- save/set_piece 的 positive P10 与 negative P90 tail gap改善；
- worst-20%视频不得继续恶化；
- 改善需大于视频级bootstrap置信区间，否则视为噪声。

结论决策：

- E1有效：Train-online mismatch成立，继续E2；
- E1无效但窗口峰值漂移严重：可小规模试E3；
- E1/E2无效且长视频错误集中在不可见局部证据：优先E4；
- E4仅提高heatmap、不提高事件指标：停止扩大检测loss，检查token routing/因果利用；
- 所有路线都只降低 sampled loss、不改善外部长视频：优先处理标签完整性和跨视频domain shift，不继续堆结构。


## 8. E1.1 修正版实现与运行记录（2026-08-25）

E1 epoch1 审计确认 `clean_negative_rank_pairs=0`：训练器曾通过 `sample_id.startswith("neg_")` 推断 clean negative，而 online records 使用 `online_chunk_*`，导致配置权重为0.2的排序约束静默失效。E1只保留为故障对照，不作为Online-simulation结论。

- 固定10s/stride5网格保留，anchor落在3-7s为primary positive，边界positive权重0.5；

128-chunk预检中，四个rank的active class pair分别为49/43/49/69；正式训练step40：

clean_negative_rank_positive_logit=0.60

说明静默失效已修复，正负相对约束真实参与反向传播。

## 9. E15 context-span 与 Online Validation 口径修订（2026-08-26）

### 9.1 Context span 不再通过抬高全 span 绝对概率加强

E15 首轮使用 `mean_probability_floor=0.25` 作为弱安全约束。审计确认 span mask 是活的，但有效 span row 内的条件平均概率已约为 0.46，大部分样本自然满足 0.25 floor；加权后的 context loss 相对总 loss 几乎为零。这一信号只能解释为“防止 context coverage 坠底”，不能解释为有效的 set-piece 增益来源。

下一版禁止简单提高全 span 的绝对概率 floor。set-piece 是长上下文事件，全 span 抬分会把门前聚集、静止站位等常见背景一起抬高，增加 dense FP。

预注册的替代方向是同视频、弱相对监督：

```text
TopKMean(P_set_piece(raw accepted span))
    > TopKMean(P_set_piece(same-video matched background)) + small_margin
```

实施约束：

- 只使用 human-accepted/raw-valid span，reviewed-rejected span 继续作 ignore zone；
- background 从同视频、相近场景中匹配，避免球场/domain 捷径；
- 使用 top-k/soft-top-k 而不是全 span mean，不要求每一帧都是事件；
- margin 小权重、warm-in，不取代 clip head 和 reviewed anchor；
- 必须报告 active pair 数、violation fraction、span/background score gap 和加权后实际 loss mass；
- 只有 set-piece AP/Online Val15 FP 改善时才能归因为 context 信号有效。

### 9.2 E15 当前评测口径的已知问题

E15 当前运行中，每个 epoch 的 validation 仍是 sampled/centered Val15，不是完整长视频 online dense grid。启动脚本只在四轮训练全部完成后，对 sampled-val 选出的 `best.pt` 补跑一次 Online Val15。

这会导致 sampled-val 决定 `best.pt`，而 online-simulation 的真实目标是 PointNMS 1:1 事件指标和人工参与度；两者已观测到可能反向变化，因此当前选模链路不完整。

后续 online-simulation 实验的正式口径修订为：

- sampled/centered Val15 只作诊断，输出 mAP/AUROC、frame-topk 和 positive-tail；
- Online Val15 使用完整 10s/stride5 grid、frame-response peak、PointNMS、strict 1:1、tol=5s；
- shot 使用 `precision @ recall>=0.85`，save/set-piece 使用无 recall floor 的 event-level F1；
- `best.pt` 必须由 Online Val15 mixed objective 选择，不再由 sampled clip F1 单独选择；
- 每 epoch 保存 Online Val15 prediction cache，阈值/NMS/UI时长离线重算不重复解码；
- 评测完成后仅保留 online-best 和 last checkpoint，中间临时权重可删除；
- External18 仍使用 Online Val15 固化阈值，不参与选模、早停或阈值搜索。

当前 E15 已启动，不在 epoch 边界中断或抢占训练 GPU。本轮结束后至少对 `best.pt` 和 `last.pt` 用同一 Online Val15 口径对比，并在下一轮将 Online Val15 前移为 checkpoint selection 的主口径。
