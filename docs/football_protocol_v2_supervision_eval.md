# Football event protocol v2: supervision and evaluation

## Core diagnosis

The current plateau should be treated primarily as a supervision/target-design bottleneck, not a capacity bottleneck. Architecture changes, LoRA/full fine-tuning, video backbones, and SSL adaptation have produced mostly noise-scale movement, while false-positive analysis shows many far FPs overlap with discarded non-target football actions.

## Other-action hard-negative policy v1

Use hard negatives before promoting `other_action` to an explicit output class.

Allowed first-version raw labels:

- 拦截
- 抢断
- 解围
- 盘带
- 对抗成功

Excluded first-version labels:

- 裁判鸣哨
- 犯规 / 其他犯规类型
- whistle/foul-like windows near set pieces

Rationale: whistle/foul are strongly time-correlated with set-piece events and can damage set-piece recall if used as all-class negatives. First-version other-action HNs affect only shot/save labels.

Manifest construction rules:

- source videos: reviewed train split only, `configs/football/splits/vitl16_lvd1689m_set_piece_seed42_162videos_reviewed/train_video_ids.txt` (101 videos)
- score source: current target model dense scores on reviewed train videos; if a manifest was selected by a different checkpoint, rescore the candidate windows with `train.init_checkpoint` before training
- selection: score-filtered by model probability, not all raw actions
- default p005 manifest before target-model rescoring: `outputs/football_hard_negatives/other_action_reviewed_train_shot_save_score_filtered_p005.json`
- ST-rescored p005 manifest for ST-descended HN runs: `outputs/football_hard_negatives/other_action_reviewed_train_shot_save_score_filtered_p005_st_rescored.json`
- labels: shot/save only
- hard-negative loss weight: 4
- repeat factor: 1
- hard-negative temporal jitter: <= 0.25s
- expected effective pressure: roughly 5–10% after loss weighting

Acceptance criteria:

- primary metric: 35-val PointNMS tol=5
- recall drop <= 1 percentage point at matched operating point
- shot/save precision improves beyond video-bootstrap CI noise
- far FP drops, especially on pure-action windows
- confidence gap improves: positive p10 score vs hard-negative/negative p90 score

Decision tree:

- HN improves precision with recall drop <= 1pp: promote other_action to explicit class in v2.
- HN gap improves but recall/precision trade is poor: tune HN dose/threshold/cap once.
- HN gap does not move: stop HN line and shift resources to verifier/reranker.



## Product KPI: recall/cost Pareto frontier

The operating metric is not a single scalar. Human review cost remains a primary KPI, so threshold selection must report both sides of the same PR/cost curve:

1. `recall @ participation budget B%`: on calibration-29, choose per-class thresholds that maximize strict PointNMS recall subject to a video-duration-weighted participation budget.
2. `minimum participation @ recall target R`: on calibration-29, choose per-class thresholds that reach the recall target with the least review participation / human minutes.

Participation is measured as the merged union of candidate support intervals divided by total video duration. This is screening video duration, not necessarily total wall-clock labor. The previously quoted `59.73` minutes six-video UI anchor is under audit and must not be treated as the full merged-candidate coverage duration. The reproducible artifact at `/mnt/data_16t/football/eval_outputs/vitl16_featuremap_structured_roi_temporal_best_6videos_window_overlap_tol2/multilabel_review_segments_recall_preserving_tol2/` gives `363` merged review segments and `5371.23s = 89.52min` full segment coverage. A plausible UI-capped interpretation, `sum(min(segment_duration, 10s))`, gives `59.83min`, close to `59.73min`; therefore reports must state whether the budget is full support coverage or per-segment capped UI viewing time. Human operation time must still be reported separately as `screening_video_duration + per_candidate_overhead`; unless measured from UI action logs, use a sensitivity range of 1.3x-1.5x over screening duration, or 2-4 seconds per candidate.

Required auxiliary reports:

- candidate viewing minutes;
- estimated human minutes with operation overhead;
- candidates/hour;
- duplicate/support-window ratio;
- per-video participation outliers.

This KPI does not replace precision/recall/F1; it defines deployable operating points. HN/verifier improvements should be judged by whether the Pareto frontier improves: higher recall at the same budget, or lower cost at the same recall.

## Control/HN preregistered readout

Dense long-video readout for the ST control/HN pair is epoch-sensitive and must not rely only on best/last checkpoints. For both arms, evaluate `epoch_1.pt` through `epoch_4.pt` on 35-val PointNMS tol5. If HN improves precision at epoch 1 but degrades recall later, the epoch-1 result is admissible evidence for shortening the HN schedule rather than a failed HN mechanism.

Acceptance criteria for shot/save:

- precision improves by at least 2 percentage points at the selected operating point;
- recall drops by no more than 1 percentage point;
- micro false positives drop meaningfully;
- improvement exceeds video-cluster bootstrap noise;
- process metric improves: positive p10 score minus negative/hard-negative p90 score widens.

Decision tree:

- pass criteria: promote `other_action` from HN source to an explicit supervised class in the next experiment;
- precision/recall inconclusive but confidence gap widens: treat this as dose/selection issue and run one dose retry (`min_prob 0.05 -> 0.03`, `max_per_video_per_label 15 -> 30`);
- confidence gap does not move: stop this HN route and shift resources to verifier/reranker.

The v2 positive-data/anchor/raw-missing experiment is confounded if corrupted videos produced black-frame samples during early training. Keep any completed v2 checkpoint only as a verifier candidate; do not use it as causal evidence for the supervision changes.

## Verifier/reranker as main pipeline

The two-stage pipeline should be treated as a first-class system:

1. freeze the high-recall E1 candidate generator;
2. fit verifier/reranker on calibration 29 videos;
3. freeze thresholds on calibration 29;
4. report end-to-end PointNMS tol=5 on 35-val with bootstrap CI.

Caveat: if checkpoint selection used all 35 validation videos, holdout6 is not fully clean. Future base checkpoint selection should use calibration 29 only when validating verifier improvements.

## Manual review before dense-FP HN

Before mining the other half of far FPs from unannotated regions, manually review 50–100 far-FP/no-GT clips using `tools/football_event_review/`.

Goal:

- split missing GT true events from true background FPs;
- repair GT if needed;
- avoid poisoning the model by training real unannotated events as negatives.
