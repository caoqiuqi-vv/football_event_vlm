# 足球事件最终质检

统一启动命令、数据准备、备份和工具清单见 [UI 统一管理 README](../ui/README.md)。

这是独立于初审数据库的终审层。它不使用普通时间 NMS，而是用 GT 血缘和一对一时间关联生成 canonical event。

安全规则：

- 两个原始 GT 永不自动合并；同刻不同类事件（如 shot/save）相互独立。
- 同一 GT 与同类模型/人工结果经时间及 dense 来源证据关联后，终稿只保留一条并采用 GT 时间；原始来源证据只读保留。
- 两个无 GT 血缘的近邻人工事件不自动删除，终审必须合并或明确选择“保留近邻两条”。
- 每条决定保存 revision、source hash、reviewer 和完整历史；来源变化后已有决定变成 stale。
- 整视频初审未完成的决定是 provisional，严格导出会拒绝。
- 严格导出拒绝 unreviewed、pending、stale、来源哈希不一致以及未经 keep_both 明确确认的同类近邻事件。

当前终审队列只保留 GT 与初审人工之间的真实差异：同语义类别且时间相差不超过
5 秒时按一对一方式视为一致；GT/人工同时为空的抽检 case 不进入终审；`throw_in`
（界外球）从终审比较中排除。过滤只改变终审路由，不删除初审数据库和历史记录。

组件：

- `build_cases.py`：从只读初审 DB 和原始 GT 构建原子快照。
- `watch_cases.py`：每 60 秒重建快照。
- `server.py`：令牌保护的 HTTPS UI 和独立 SQLite 审计库。
- `export_final.py`：最终一致性校验和标注导出闸门。

当前部署：`outputs/football_event_review/test18_final_qc_20260903/`。初审 DB 不会被此工具修改。

## 终审 UI 工作流

- 左侧为大画面，底部为横向事件带；右侧固定展示 GT、模型/初审证据和最终人工结果。
- 点击案例后自动播放支持区间，到 `end_sec` 自动暂停。
- 确认后自动打开下一条未审事件，横向事件带同步将当前事件滚动到可视区域中央。
- 一个时间锚点展开显示全部类别，可直接多选并输出多个独立事件。
- 已审核事件显示绿色勾选，顶部显示当前位置和审核进度。
- 默认审核员为 `终审员1`，也可用 URL 参数 `reviewer` 指定并在浏览器本地记忆。
- 快捷键：空格播放/暂停，左右键跳转 3 秒，`[`/`]` 切换案例，Ctrl+Enter 确认保存。
