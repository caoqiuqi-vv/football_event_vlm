# 8775 视频转圈／黑屏排查与修复（2026-09-09）

## 证据与边界

用户反馈电脑 Chrome/Edge 能打开页面，但视频转圈或黑屏。检查时健康和就绪请求分别约 9/12 ms，进程没有连接堆积，148 个媒体全部 faststart 就绪。这些指标不能代替播放验收。

确认的低效点：v38 的 seekAbsolute 在未缓冲目标上清空 src 并调用 load，丢弃长视频索引并从文件开头重新传输。示例视频 1984141063636848642 的 moov 为 6,838,800 字节；全体视频索引中位数约 3.92 MiB，11 个超过 8 MiB，最大约 12.35 MiB。真实 H.264 Firefox 请求跟踪复现了远距离跳转重复读取文件开头。

旧版 Range 固定截断为 8 MiB，增加了大索引与续读的交互。本次恢复客户端请求的完整范围。但旧版在本地 Chrome 大索引合成视频中仍可播放，因此不能把这个上限断言为所有黑屏的唯一原因。另有证书拒绝与连接超时日志；本次未更换证书，用户实际公网链路没有直接测量。

## 修复

- 同视频内直接 seek，复用解析器、索引和缓存；加载中连续切换只保留最新目标，旧视频回调不能覆盖新选择。
- Range、suffix、HEAD 返回请求范围；保持定长内存读写和传输/连接并发限制，不把整段视频读入内存。
- 请求接受 gzip 时压缩大 JSON；示例视频 manifest 数据由 585,337 字节压至 49,251 字节，实际 API 大小随审核状态变化。
- 长时间缓冲有重试入口，避免仅监听 error 而一直黑屏；不进行反复自动重载。
- 记录媒体请求范围、已发送字节数、耗时和完成/断开类型；正常断开不再刷完整异常栈。

## 验证

- 23 项后端回归通过，包括大范围实际传输、HEAD/suffix、压缩协商、保存事务、幂等、归属规则、鉴权和并发。
- 4 项播放器跳转测试通过：不重载、加载中连续跳转、旧回调隔离、出错重载。
- Chromium 标注完整回归通过：事件归属、离线恢复、丢响应重试、视频乱序、配额失败、GT 删除保护、冲突草稿重新提交，页面错误为 0。
- Firefox 实际 H.264：问题视频及 12.35 MiB 索引视频首次播放、800 秒跳转通过；修复后跳转请求不再从 0 开始。
- Chromium 124 MiB VP9/MP4 及带 12 MiB 索引元数据的合成 MP4 播放和远距离跳转通过。此环境 Chromium 没有 H.264 解码器，不能据此宣称已在 Chrome 上实测生产 H.264。
- Chrome CDP 模拟 500,000 字节/秒（约 4 Mbps）、100 ms 延迟，大索引合成视频首次出画 26.275 秒，随后跳到 300 秒出画 0.263 秒。此结果说明首次索引成本仍存在，而同视频跳转可复用索引；不是用户公网 SLA。
