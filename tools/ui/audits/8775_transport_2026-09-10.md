# 8775 慢连接传输与前向缓冲

2026-09-10 21:06 左右，健康检查正常，但多个媒体请求在 15 秒内发生写入超时。抽查连接累计发送约 899 KB、重传约 193 KB，说明至少部分客户端链路存在明显重传；不能据此定位到某一网络运营方。四个故障视频文件均存在、索引在头部，本地前 16 MiB 读取约 988–1204 MiB/s（可能命中页缓存）。

## 修改

- 媒体分块从 512 KiB 调整为 32 KiB，媒体写入超时从通用 15 秒调整到 45 秒；请求完成/异常后恢复原超时。登录、请求头和 API 超时不变。
- 仍保留 16 个媒体并发槽和 128 个连接槽；断连及时释放。45 秒是单次写入等待上限，不是整段视频下载时限。长期没有进展的连接仍会断开。
- 媒体使用 private 缓存并按 Cookie 区分，复用时必须重新校验；保持 ETag、版本 URL、Range 和访问授权。
- 复用当前 video 的索引和缓冲区。当当前画面可播放，且下一未审事件位于当前位置后 30 秒以内时，将 preload 提示设置为 auto，目标为下一事件起点后 8 秒；缓冲达到目标后恢复 metadata。
- 弱网提示（2G/3G、低于 2 Mbps）、省流、后台页面、跳转及报错时不主动预加载；waiting/stalled 后退避 30 秒。未另开视频、连接，也未通过 seek/load 改变正在查看的画面。

## 边界

preload 是浏览器提示，不是可强制执行的下载配额。浏览器决定实际缓冲范围，metadata 也不保证立即取消已开始的传输；播放期间仍按播放需求读取。远距离下一事件不做随机预取，不能承诺任意事件切换零等待。缺少 Network Information API 的浏览器仍通过播放状态和 stalled/waiting 退避。

该优化不能消除公网丢包，也没有改变原视频码率或索引大小。首次加载大索引依然需要时间。新增缓冲控制器兼容切换前的旧后端，避免发布期间静态文件读取导致前端异常。
